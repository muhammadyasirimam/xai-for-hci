What is Explainable AI?

XAI refers to methods and techniques that make AI system decisions understandable to humans. It bridges the gap between complex ML models and human interpretability — a core concern in Human-Computer Interaction.

Why HCI Needs XAI

Users need to trust, verify, and appropriately rely on AI. Without explanations, users either over-trust or dismiss AI outputs. XAI transforms AI from a black box into a collaborative partner.

How It Works
The Model

This demo uses a weighted linear scoring model — a simplified but pedagogically clear version of how many real-world credit scoring systems work. Each input feature is normalized to [0, 1], multiplied by a learned weight, and summed with a base approval rate.

score = base + Σ(wi × norm(xi)) If score ≥ 50% → Approved · If score < 50% → Rejected

The base rate is 52% — meaning a completely average applicant is slightly more likely to be approved than rejected. Each feature then shifts this probability up or down.

Explanation Techniques

Each tab in the dashboard demonstrates a different XAI approach — all computed from the same underlying model:

Local (SHAP)
Shows how each feature pushed this specific prediction above or below the 50% threshold. Inspired by SHAP (SHapley Additive exPlanations).
Global Importance
Shows which features matter most in general across all possible inputs, based on absolute weight magnitudes.
Counterfactual
Answers "What would I need to change?" — computes the minimum feature modifications needed to flip a rejection to approval.
Decision Path
Decomposes the decision into a sequence of yes/no checkpoints, mimicking a simplified decision tree for transparent reasoning.
How SHAP Values Are Computed

The SHAP-like contribution for each feature is calculated as:

shapi = wi × ( norm(xi) − 0.5) 0.5 represents the "average" input — positive SHAP means this feature pushed the score above average.

A positive SHAP value (green bar) means the feature's value is above average and pushed the decision toward approval. A negative SHAP value (red bar) means it pushed toward rejection. The bars are centered at zero, just like real SHAP waterfall plots.

How Counterfactuals Work

When the loan is rejected, the system calculates the deficit — how far below 50% the score falls. For each feature with a positive weight, it computes how much that feature would need to increase to cover the deficit. For features with a negative weight, it computes how much to decrease the feature value.

Changes requiring more than 40% of the feature's total range are flagged as "large change" (yellow label) — signaling they may be impractical. This is an HCI design choice to set realistic expectations.

HCI Design Principles Used
🎯 Progressive disclosure — Tabs prevent overwhelming users with all explanations at once. They choose what to explore.
🎨 Color semantics — Green/red maps to universal "good/bad" mental models. No jargon like "positive coefficient."
🎮 Interactive exploration — Sliders let users test "what if" scenarios, turning passive explanation into active understanding.
⚡ Actionable counterfactuals — Instead of just explaining "why rejected," the system tells users "what to change" — the most useful explanation type per HCI research.
⚠ Disclaimer: This is an educational demonstration, not a real credit scoring system. The model is intentionally simplified to make explainability techniques clear. Real-world systems use non-linear models, additional features, regulatory constraints, and rigorous fairness auditing.
